# MacroWatch 기업 이익 V2 SPEC

상태: 사용자 승인  
기준일: 2026-09-01  
구현 상태: 백필 전 기반 구현

## 1. 목적

기업 이익 V2는 한국과 미국의 분기 재무자료와 당시 시가총액 유니버스를 이용해 다음 정보를 빠르고 일관되게 제공한다.

- 시장별 평균 영업이익·순이익 추이
- 시장별 영업이익·순이익 YoY 변화율
- 시장별 영업이익·순이익 계절조정 QoQ 변화율
- 개별기업의 동일한 세 가지 그래프

V2는 V1의 수정판이 아니다. V1을 참조하지 않는 독립 파이프라인으로 구축하고, 검증과 전환이 끝나면 V1을 한 번의 제거 작업으로 폐기할 수 있어야 한다.

## 2. 확정 원칙

1. 화면에 뿌려주는 데 필요한 원자료와 최종 계산값을 저장한다.
2. 다시 수집하기 어렵고 활용 목적이 분명한 기초 사실은 현재 화면에 쓰지 않더라도 저장할 수 있다.
3. 기존 저장값으로 빠르게 재계산할 수 있는 중간값은 저장하지 않는다.
4. 프론트엔드는 재무 계산을 하지 않는다. 무거운 계산은 수집·갱신 배치에서 끝내고 결과를 저장한다.
5. 미래 분기는 목표 기업 수와 필수 재무값을 모두 채워야 확정한다. 미달 결과를 정상 결과처럼 공개하지 않는다.
6. 과거 분기는 미리 낮은 커버리지를 가정하지 않는다. 매년 목표 수를 모두 채우는 것을 우선하며, 한 해씩 결과와 미확보 사유를 확인한 뒤 다음 연도 진행 여부를 사용자가 결정한다.
7. 없는 값을 추정하거나 다른 지표로 대체하지 않는다.
8. V2 검증이 끝날 때까지 V1 DB·코드·자동화·화면을 변경하거나 삭제하지 않는다.

## 3. 시장 유니버스

### 3.1 목표 시장

| 시장 | 목표 기업 수 | 후보 범위 |
| --- | ---: | --- |
| 한국 유가증권시장 | 100 | 해당 분기말 KOSPI 상장 적격 보통주 |
| 한국 코스닥시장 | 50 | 해당 분기말 KOSDAQ 상장 적격 보통주 |
| 미국 대형주 시장 | 100 | 해당 분기말 미국 상장 적격 보통주 전체 |
| 미국 Nasdaq 시장 | 100 | 해당 분기말 Nasdaq 상장 적격 보통주 |

시장 표시 이름은 구현·화면 설계 때 조정할 수 있다. 공식 지수 구성종목을 복원한 것이 아니라면 공식 지수와 혼동되는 이름을 사용하지 않는다.

### 3.2 한국 분기별 선정 순서

한국은 검증 가능한 당시 전체 시가총액 순위가 존재하는 분기에 그 자료를 최우선으로 사용한다.

1. 해당 분기말 마지막 거래일의 KOSPI·KOSDAQ 전체 시가총액 순위를 조회한다.
2. 분기말 당시 상장 상태와 적격 증권 여부를 확인한다.
3. 통화·증권종류·중복기업 규칙을 적용한다.
4. KOSPI 상위 100개와 KOSDAQ 상위 50개를 직접 선정한다.
5. 최종 기업·순위·시가총액·기준 거래일을 영구 저장한다.

검증 가능한 전체 시가총액 순위를 확보하지 못한 과거 분기에만 3.3의 매출 후보 기반 복원 절차를 사용한다. 직접 시가총액 순위를 구할 수 있는 분기에 매출 순위를 선행 필터로 사용하지 않는다.

### 3.3 미국 및 한국 보조 복원 절차

각 시장과 분기마다 다음 절차를 독립적으로 실행한다.

1. 분기말 당시 상장 상태와 적격 증권 여부를 확인한다.
2. 당시 이용 가능한 최근 4개 분기 매출 또는 상단 수익을 합산한다.
3. 합산값 기준 상위 500개를 시가총액 계산 후보로 선정한다.
4. 후보의 분기말 정규장 종가와 당시 발행주식 수로 시가총액을 계산한다.
5. 시가총액 내림차순으로 목표 기업 수를 선정한다.
6. 최종 기업·순위·시가총액·기준 거래일만 영구 저장한다.

최근 4개 분기 합계와 후보 순위는 계산 중에만 사용하고 영구 저장하지 않는다.

한국에서는 전체 시가총액 순위를 구할 수 없는 과거 분기에만 이 절차를 적용한다. 미국에서는 과거 전체 시가총액 순위가 직접 제공되지 않으므로 기본 복원 절차로 사용한다.

### 3.4 신규상장·상장폐지·기업행위

- 분기말 전에 상장폐지된 증권은 해당 분기 후보에서 제외한다.
- 분기말 이후 상장폐지된 증권은 직전 분기말에는 포함할 수 있다.
- 최근 4개 분기 매출이 없는 신규상장기업은 별도 신규상장 후보로 추가해 분기말 시가총액을 계산한다.
- 합병·분할·티커 변경은 기업 식별자와 증권 유효기간으로 연결한다.
- 동일 기업의 복수 주식 종류와 ADR은 이중 집계하지 않는다.
- ETF·ETN·펀드·우선주·SPAC·테스트 종목 등 비적격 증권은 제외한다.

### 3.5 시장 간 중복기업

미국 대형주 시장과 Nasdaq 시장은 각자 후보 범위와 순위를 계산한다. 같은 기업이 두 시장에 포함될 수 있다.

- 기업과 분기 재무자료는 기업 식별자 기준으로 한 번만 저장한다.
- 시장 소속·순위·시장 평균 계산은 시장별로 각각 저장한다.
- 동일 시장 안에서는 동일 기업을 한 번만 포함한다.

### 3.6 통화

- 한국 시장은 KRW 보고 기업만 포함한다.
- 미국 시장은 USD 보고 기업만 포함한다.
- 다른 통화 보고 기업은 제외하고 다음 순위 기업으로 목표 수를 채운다.
- 환율을 이용한 임의 환산값은 유니버스와 재무 그래프에 사용하지 않는다.

## 4. 저장 재무항목

기업·분기별로 다음 세 값을 저장한다.

- 상단 수익: 일반기업 매출액 또는 금융회사 영업수익
- 영업이익
- 전체 순이익

순이익은 지배주주 귀속 순이익이 아니라 공시된 전체 순이익을 사용한다. 한 분기라도 누락시키지 않는 것을 목표로 실제 공시자료에서 해당 값을 끝까지 탐색한다. 다만 다른 계정을 순이익으로 억지 대체하거나 추정값을 만들지는 않는다. 값을 확보하지 못한 미래 분기는 완료 처리하지 않는다.

### 4.1 연결 범위

- 연결재무제표가 존재하면 연결 값을 사용한다.
- 연결재무제표가 존재하지 않는 기업은 별도재무제표 값을 사용한다.
- 같은 기업·분기 안에서 연결과 별도 값을 섞지 않는다.
- 연결 범위가 바뀐 경우 범위 정보를 함께 보존하고 검증 대상에 포함한다.

### 4.2 금융회사 상단 수익

금융회사는 계정명이 `매출액`인지 여부에 의존하지 않는다.

1. 영업이익 위에 있는 검증된 총수익·영업수익 총계가 있으면 이를 우선한다.
2. 적절한 총계가 없으면 영업이익 위의 개별 수익 항목을 합산한다.
3. 이자수익·보험수익·수수료수익 등 수익 항목은 포함한다.
4. 비용·원가·손실 항목은 제외한다.
5. 총계·소계와 세부항목을 동시에 합산하지 않아 이중계산을 막는다.
6. 사용 방식은 `reported_total` 또는 `financial_income_sum`으로 기록한다.

한국과 미국, 현재와 과거 분기에 같은 원칙을 적용한다.

### 4.3 단일 분기 변환

- Q1: Q1 누적값을 단일 분기값으로 사용한다.
- Q2: 신뢰 가능한 3개월 값이 있으면 우선하고, 없으면 H1 누적값에서 Q1 누적값을 뺀다.
- Q3: 신뢰 가능한 3개월 값이 있으면 우선하고, 없으면 9M 누적값에서 H1 누적값을 뺀다.
- Q4: FY 누적값에서 9M 누적값을 뺀다.

차감에 사용하는 값은 회계기간·통화·연결 범위가 같아야 한다.

## 5. 증가율과 상태

영업이익과 순이익을 각각 독립적으로 계산한다.

### 5.1 YoY

현재 분기와 전년 동기 값이 모두 정상적인 양수이면 일반 증가율을 사용한다.

`YoY = (현재 분기 - 전년 동기) / 전년 동기 × 100`

다음 상태에서는 숫자 증가율을 만들지 않는다.

- 흑전
- 적전
- 적자 지속·적자 축소
- 적자 지속·적자 확대
- 비교값 0
- 통화 불일치
- 연결 범위 불일치

이 상태의 증가율 값은 `NULL`로 저장하고 상태 코드를 저장한다.

### 5.2 QoQ 계절조정

정상적인 양수 분모의 일반 QoQ만 계절조정에 사용한다.

1. 현재 분기와 직전 분기의 일반 QoQ를 계산한다.
2. 현재 시점보다 과거인 동일 회계분기 전환만 조회한다.
3. 최대 과거 15년 범위에서 최근 유효표본 최대 10개를 사용한다.
4. 유효표본이 2개 미만이면 계절조정 값을 만들지 않는다.
5. 유효표본 중앙값을 계절 기준으로 사용한다.
6. `계절조정 QoQ = 현재 일반 QoQ - 계절 기준 중앙값`으로 계산한다.

흑전·적전·적자 지속·0 분모·통화 불일치·연결 범위 불일치는 계절조정 숫자를 만들지 않고 상태만 저장한다. 미래 자료는 과거 계절 기준에 사용하지 않는다.

### 5.3 Delta

YoY Delta와 QoQ Delta는 V2에서 저장하지 않는다. 필요해지는 시점에 인접한 저장 증가율로 계산한다.

## 6. 시장 그래프 집계

시장 그래프는 해당 분기의 최종 유니버스 기업값의 산술평균을 사용한다.

- 목표 수가 고정되어 있으면 합계와 평균은 상수배 관계이므로 그래프 방향과 증가율이 같다.
- 과거에 일부 기업을 확보하지 못한 경우 기업 수 변화가 합계 급변으로 보이는 왜곡을 줄이기 위해 평균을 유지한다.
- 실제 기업 수와 목표 기업 수를 항상 함께 저장한다.

시장 YoY와 계절조정 QoQ는 기업별 증가율을 평균하지 않는다. 먼저 각 분기의 시장 평균 영업이익·순이익 시계열을 만든 뒤, 그 평균 시계열에 5장의 동일한 증가율·상태·계절조정 규칙을 적용한다. 각 시점의 평균은 그 시점에 확정된 당시 유니버스를 사용한다.

미래 분기는 목표 기업 수와 필수 재무값이 모두 확보되어야 `complete`가 된다. 목표 미달 결과는 재시도하고, 계속 실패하면 관리자 확인 대상으로 남기며 정상 그래프에 확정값으로 공개하지 않는다.

과거 분기는 사전 최소 커버리지 기준을 두지 않는다. 1년씩 목표 수를 채우는 작업을 수행하고, 각 연도마다 다음을 사용자에게 보고한다.

- 분기별 목표 기업 수
- 분기별 최종 유니버스 확보 수
- 필수 재무값 확보 수
- 미확보 기업과 구체적인 이유
- 계산 가능한 시장 분기 수

사용자 확인 없이 부족한 기업을 평균·추정값으로 채우거나 다음 연도로 넘어가지 않는다.

## 7. 화면 계약

### 7.1 시장 화면

각 시장에 다음 세 그래프를 제공한다.

1. 평균 영업이익·평균 순이익
2. 영업이익·순이익 YoY
3. 영업이익·순이익 계절조정 QoQ

프론트엔드는 완성된 시장 분기 행을 조회해 그리기만 한다.

### 7.2 손익 전환 표시

- 원이익 그래프는 음수와 양수를 그대로 연결한다.
- 증가율 그래프는 계산 불가능한 분기에서 선을 끊는다.
- 그래프 중간 높이에 `흑전`, `적전`, `적자 축소`, `적자 확대` 텍스트를 표시한다.
- 앞뒤 정상 구간을 임의 실선이나 점선으로 연결하지 않는다.
- 마우스 세로선 상단에는 실제 이전값·현재값과 상태를 표시한다.

예: `영업이익 -50억 → +100억 · 흑전`

### 7.3 개별기업 화면

개별기업도 시장 화면과 동일한 세 그래프를 사용한다. 기업 선택 UI는 아직 확정하지 않는다.

잠정안은 다음과 같다.

- 처음 열면 해당 분기 시가총액 1위 기업 표시
- 드롭다운에서 해당 시장 기업 선택
- 선택하면 같은 그래프 영역의 데이터 교체

UI 방식은 DB 백필과 계산 규칙을 변경하지 않는다.

## 8. V2 최소 저장 구조

V2는 같은 Supabase 프로젝트 안의 독립 `earnings_v2` 영역으로 구축한다. V1 객체를 외래키·함수·코드로 참조하지 않는다.

### 8.1 기업

기업·증권 식별과 유효기간에 필요한 최소정보를 저장한다.

- 기업 ID
- 국가·시장
- 기업명
- 티커
- SEC CIK 또는 DART 기업코드
- 거래소
- 보고 통화
- 상장·상장폐지 및 식별자 유효기간

### 8.2 기업 분기

기업·회계분기당 한 행으로 다음을 저장한다.

- 기간 시작·종료일과 시장 분기
- 분기 상단 수익
- 영업이익
- 전체 순이익
- 통화·연결 범위
- 상단 수익 계산 방식
- 영업이익·순이익 YoY 값과 상태
- 영업이익·순이익 계절조정 QoQ 값과 상태
- 공시 식별자·공시일·정정 기준일
- 품질 상태·계산 버전

### 8.3 분기 유니버스

최종 선정 기업만 저장한다.

- 시장
- 기준 연도·분기
- 기준 거래일
- 기업 ID
- 최종 시가총액 순위
- 분기말 시가총액과 통화

### 8.4 시장 분기

프론트가 바로 읽을 수 있는 시장 결과를 저장한다.

- 시장·분기
- 평균 영업이익·순이익
- 각각의 YoY 값과 상태
- 각각의 계절조정 QoQ 값과 상태
- 실제 기업 수·목표 기업 수
- 완료 상태·계산 버전

### 8.5 자동수집 상태

누락 없는 증분 수집과 멱등성을 위해 소스별 마지막 성공 체크포인트와 현재 작업 상태만 보존한다. 실행별 원본 응답이나 무제한 로그 이력은 저장하지 않는다.

## 9. 저장하지 않는 값

- API 원본 응답 JSON
- 전체 재무제표 원천 행
- 최근 4개 분기 합계
- 매출 후보 순위
- 후보 500개 중 탈락기업의 중간 시가총액
- 계절조정 표본 배열과 중앙값 계산 과정
- YoY·QoQ Delta
- 검증용 복제 테이블
- 테스트용 운영 DB 데이터
- 화면·자동화·재현에 필요하지 않은 파생값

임시 계산은 작업자 메모리 또는 트랜잭션 임시 테이블에서 수행하고 작업 종료와 함께 폐기한다.

## 10. 인덱스·보안·접근

- 기업 분기 조회는 기업 ID·연도·분기 고유키를 사용한다.
- 시장 분기 조회는 시장·연도·분기 고유키를 사용한다.
- 유니버스 순위는 시장·연도·분기·순위 고유성을 보장한다.
- 프론트 조회 경로에 필요한 복합 인덱스만 만든다.
- V2 테이블은 RLS 또는 비공개 스키마와 제한된 조회 함수를 통해 보호한다.
- 서비스 역할 키와 공급자 API 키는 브라우저·DB·로그에 저장하지 않는다.
- 프론트는 쓰기 권한을 갖지 않는다.

## 11. 백필 순서

1. V2 스키마와 독립 수집·계산 모듈을 만든다.
2. 최신 1년 4개 분기를 파일럿 백필한다.
3. 최신 시총 순위를 현재 공급자 값과 비교한다.
4. 기업 수·통화·연결 범위·중복·이상치·증가율 상태를 검사한다.
5. 사용자에게 시장·분기별 확보 수와 누락 사유를 보고한다.
6. 사용자가 승인하면 그 이전 1년을 백필한다.
7. 같은 절차로 1년씩 과거로 진행한다.
8. 사용자 승인 없이 여러 연도를 연속 백필하지 않는다.

과거 데이터가 부족해도 값을 만들거나 다른 기업의 평균으로 채우지 않는다. 실제 확보값과 원인을 보고한 뒤 사용자가 해당 연도의 표시 여부를 결정한다.

## 12. 자동수집과 재계산

- 신규 공시가 발견되면 해당 기업·분기 원자료를 갱신한다.
- 정정공시는 동일 분기 행을 최신 실제 공시값으로 교체한다.
- 변경된 기업의 YoY와 QoQ에 영향을 받는 분기만 재계산한다.
- 해당 기업이 속한 모든 시장의 영향받는 분기 결과만 재계산한다.
- 미래 분기 목표 기업 수와 필수값이 완성되기 전에는 확정 결과를 공개하지 않는다.
- 수집 실패는 체크포인트를 전진시키지 않으며 다음 실행에서 누락 구간을 재시도한다.

## 13. V1 격리와 폐기

V2는 다음 단위로 V1과 분리한다.

- DB: `earnings_v2` 전용 영역
- Python: `backend/earnings_v2/`
- Edge Function: `earnings-v2-*`
- GitHub Workflow: `earnings-v2-*`
- 프론트 조회 함수: `get_earnings_v2_*`

V2 구현과 동시에 V1 폐기 대상을 기록한 retirement manifest를 유지한다. V2 백필·자동수집·프론트 전환이 모두 검증된 뒤에만 다음을 한 번의 제거 작업으로 수행한다.

1. V1 자동화 중지
2. V1 DB 함수·트리거·테이블 제거
3. V1 Edge Function·Python·Workflow 제거
4. V1 프론트 호출부 제거
5. 남은 참조·예약 실행·RLS·DB advisor 검사

파괴적 제거는 별도 사용자 승인 전에는 실행하지 않는다.

## 14. V2에서 제외하는 기능

- 매출 그래프의 초기 화면 표시
- YoY·QoQ Delta 저장 및 그래프
- 기업 간 다중 비교 그래프
- 원본 공시 전문 보관
- 후보 500개 이력 화면
- 순위 예측 또는 결측값 추정

매출 분기값은 후보 선정과 향후 활용을 위해 저장하지만 초기 화면에는 표시하지 않는다.
