# Earnings Momentum 데이터 계약

이 문서는 `SPEC_Earnings_Momentum_Leaders.md`를 MacroWatch의 Supabase/PostgreSQL 구조와 기존 자동수집 방식에 맞게 구체화한 구현 계약이다. 원본 명세의 분석 목적과 계산 원칙은 유지하고, 저장소·보안·정정공시 처리만 실제 시스템에 맞게 조정한다.

## 1. 데이터 계층

DB에는 MacroWatch가 실제 사용하는 정보만 저장한다.

1. **공시 식별 이력**: `earnings_filings`
   - 공시 접수번호·발표일과 정정 관계만 보존한다.
   - OpenDART 응답 본문과 개별 원천 행은 작업자 메모리에서 해석한 뒤 폐기한다.
2. **현재 표준 분기값**: `earnings_quarterly_financials`
   - 집계에 사용할 단일 분기 매출·영업이익·순이익만 저장한다.
   - 정정공시가 오면 해당 분기를 최신 filing 기준으로 교체한다.
   - YoY, QoQ, 각 변화율의 Delta, 순위, Leader Score는 이후 파생계층에서 계산한다.

기업과 지수 소속도 분리한다. 기업은 `earnings_companies`에 한 번만 존재하고, 복수 지수 소속은 `earnings_index_memberships`에 각각 저장한다. 정기 수집 대상은 하나 이상의 현재 유효한 지수 소속이 있는 기업으로 한정한다.

여기서 네 유니버스는 공식 지수 상품의 구성종목을 뜻하지 않는다. 기존 `index_id`는 호환성을 위해 유지하되 실제 의미는 다음과 같다.

- `SP100`: S&P 500 구성종목 중 시가총액 상위 100개
- `NASDAQ100`: NASDAQ 상장종목 중 시가총액 상위 100개
- `KOSPI100`: KOSPI 상장종목 중 시가총액 상위 100개
- `KOSDAQ50`: KOSDAQ 상장종목 중 시가총액 상위 50개

각 날짜의 순위와 시가총액은 `earnings_universe_snapshots`에 보존한다. 완전한 목표 개수의 스냅샷을 확보한 경우에만 소속 이력을 교체하며, 공급자가 일부 행만 반환하면 기존 소속을 유지한 채 실행을 실패 처리한다. 한국은 KIS가 인증 없이 제공하는 KOSPI·KOSDAQ 종목 마스터의 전일 시가총액을 사용한다. 이 경로는 앱키·접근 토큰·초당 API 호출 한도를 사용하지 않아 ETF 수집과 경합하지 않는다. 마스터의 ETP·SPAC·우선주 구분 필드로 비기업 또는 보통주가 아닌 행을 제외한다. ETP는 불리언이 아니라 분류 코드이므로 `Y`·`1`뿐 아니라 비어 있지 않은 모든 유효 분류값을 제외한다. KIS 국내 시가총액 순위 API는 실제 응답이 시장별 30개로 제한되어 100개 유니버스의 원천으로 사용하지 않는다. OpenDART `corp_code` 연결은 공시 수집기가 별도 수행한다. 실적·공시·재무 수집은 OpenDART 다중기업 API를 기본 경로로 사용한다.

미국은 KIS 해외 시가총액 순위를 사용한다. `SP100`은 공개 S&P 500 구성종목 안에서만 상위 100개를 선택하고, `NASDAQ100`은 Nasdaq 공식 종목 디렉터리에서 ETF·NextShares·테스트 종목이 아니라고 확인된 NASDAQ 상장기업 안에서 상위 100개를 선택한다. 두 유니버스는 소속·순위·집계·그래프를 완전히 별도로 유지한다. 동일 SEC CIK 기업이 양쪽에 겹치면 재무 원자료는 한 번만 저장하고 두 소속이 공통 기업자료를 각각 참조한다. 같은 기업의 복수 주식 종류는 CIK로 중복 제거한다.

## 2. OpenDART 기본 수집 경로

한국 기업은 다음 순서로 수집한다.

1. `corpCode.xml`로 종목코드와 `corp_code`를 동기화한다.
2. 공시목록 API로 신규 사업·반기·분기보고서와 정정공시를 탐지한다.
3. 주요계정 다중회사 API `fnlttMultiAcnt.json`을 기본 재무 수집 경로로 사용한다.
4. 중복 기업을 제거한 `corp_code`를 최대 100개씩 묶는다.
5. 동일 사업연도·보고서 코드별로 배치 호출한다.
6. 다중회사 응답에서 필수 계정이 누락된 기업만 `fnlttSinglAcntAll.json`으로 보완한다.

OpenDART 보고서 코드는 다음과 같이 해석한다.

| 보고서 코드 | 의미 | 목표 분기 |
| --- | --- | --- |
| `11013` | 1분기보고서 | Q1 |
| `11012` | 반기보고서 | Q2 |
| `11014` | 3분기보고서 | Q3 |
| `11011` | 사업보고서 | Q4 |

OpenDART 응답은 저장하지 않는다. 같은 기업·사업연도·보고서코드 작업은 작업 큐와 표준 분기값의 고유키로 중복 처리를 막는다.

## 3. OpenDART 계정 선택

수집 metric은 `revenue`, `operating_income`, `net_income` 세 개뿐이다. EPS는 파싱하거나 저장하지 않는다.

- 정확한 계정명 문자열 하나에 의존하지 않는다.
- 우선 표준 계정 ID를 사용하고, 허용된 계정명 별칭은 명시적인 매핑 테이블 또는 코드 상수로 관리한다.
- 연결재무제표(`CFS`)를 우선한다.
- 연결 값이 없을 때만 별도재무제표(`OFS`)를 사용한다.
- 한 분기의 metric을 CFS와 OFS에서 임의로 섞지 않는다.

## 3.1 SEC 기본 수집 경로

미국 기업은 인증키가 필요 없는 SEC `companyfacts` API를 사용한다. SEC CIK별 응답 한 번에서 최근 10년의 10-Q·10-K·정정공시를 해석하고 공급자 응답 본문은 저장하지 않는다. 요청에는 MacroWatch를 식별하는 User-Agent를 포함하고 초당 10회보다 느린 공통 요청 간격을 적용한다.

미국도 `revenue`, `operating_income`, `net_income`만 저장한다. 표준 US-GAAP 태그를 우선순위가 있는 명시적 별칭으로 관리하고, Q1~Q3는 3개월 단일기간 값을 선택한다. Q4 단일값이 없으면 연간값에서 Q1~Q3를 차감한다. 세 핵심값 중 하나라도 확정할 수 없는 분기는 NULL 행을 만들지 않고 누락 분기로 보류한다. 정정 10-Q/A·10-K/A는 동일 기간의 이전 SEC 공시를 연결해 표준 분기를 교체한다.

## 4. 단일 분기값 변환

공급자가 제공한 당기 단일기간 값과 누적값을 구분한다.

- Q1: Q1 누적값을 단일 분기값으로 사용한다.
- Q2: 반기보고서에 신뢰 가능한 3개월 당기값이 있으면 그 값을 우선한다. 없으면 H1 누적값에서 Q1 누적값을 뺀다.
- Q3: 3분기보고서에 신뢰 가능한 3개월 당기값이 있으면 그 값을 우선한다. 없으면 9M 누적값에서 H1 누적값을 뺀다.
- Q4: 사업보고서 FY 누적값에서 9M 누적값을 뺀다.

차감에 필요한 앞 분기 누적값이 없거나 회계기간·통화·연결구분이 다르면 전체 재무제표와 이전 공시를 다시 조회한다. 그래도 필수값을 확보하지 못하면 해당 분기는 `review_required`로 보류하며, 불완전한 `NULL` 값을 모멘텀 계산에 투입하지 않는다.

## 5. 성장률과 QoQ 계절조정

매출·영업이익·순이익 각각에 대해 원값을 보존하면서 다음 파생값을 별도 계층에 계산·저장한다.

- `yoy`: 현재 단일 분기값의 전년 동기 대비 증감률
- `yoy_delta`: 현재 YoY에서 직전 분기 YoY를 뺀 성장 가속도
- `qoq_raw`: 현재 단일 분기값의 직전 분기 대비 증감률
- `qoq_seasonal_baseline`: 확보된 최근 5년 안에서 같은 회계분기 전환에 해당하는 `qoq_raw`의 중앙값
- `qoq_seasonally_adjusted`: `qoq_raw - qoq_seasonal_baseline`
- `qoq_seasonally_adjusted_delta`: 현재 계절조정 QoQ에서 직전 분기 계절조정 QoQ를 뺀 값

YoY는 같은 회계분기끼리 비교하므로 별도의 계절조정을 적용하지 않는다. QoQ는 기업·metric·회계분기별로 서로 독립된 계절 기준을 사용한다. 확보된 표본 수와 계산법도 함께 저장해 적은 표본으로 계산된 값을 구분하고, 원본 QoQ를 계절조정값으로 덮어쓰지 않는다.

QoQ와 그 계절조정 파생값은 분석·표시용이다. 초기 Leader Score에는 넣지 않고, 기존 원칙대로 분기 주가수익률 percentile 60%와 영업이익 YoY percentile 40%만 사용한다.

## 6. 분기 식별

다음 값을 함께 저장한다.

- `fiscal_year`, `fiscal_quarter`: 기업 회계연도 기준
- `period_start`, `period_end`: 실제 보고기간
- `market_year`, `market_quarter`: 지수 집계 기준

한국 초기 버전은 원칙적으로 회계분기와 시장분기를 동일하게 매핑하되 실제 `period_end`를 반드시 검증한다. 미국 기업은 비달력 회계연도가 흔하므로 SEC 어댑터 구현 전에 별도 시장분기 매핑 규칙을 확정한다.

## 7. 정정공시와 멱등성

정정공시는 원공시를 덮어쓰지 않는다.

1. 새 `earnings_filings` 행을 만들고 가능한 경우 `corrects_filing_id`를 연결한다.
2. 유효한 최신 공시를 선택해 `earnings_quarterly_financials`를 교체한다.
3. `canonical_version`을 증가시킨다.
4. 이후 단계에서 해당 분기와 영향을 받는 후속 Delta·지수집계·순위를 재계산한다.

재시도 시에는 다음 키로 중복을 방지한다.

- 공시: source + source_filing_id
- 표준 분기값: company_id + fiscal_year + fiscal_quarter

## 8. 보안과 공개 범위

- GitHub Actions와 백엔드는 `SUPABASE_SERVICE_ROLE_KEY`로 적재한다.
- OpenDART API 키는 `OPENDART_API_KEY` 환경변수에서만 읽고 DB·로그에 남기지 않는다.
- 공시 이력은 클라이언트 읽기 정책을 만들지 않는다.
- 로그인 사용자는 기업·지수·소속·표준 분기값만 읽을 수 있다.
- 관리자 교정 기능이 필요해지면 브라우저에서 원본 테이블을 직접 수정하지 않고 관리자 Edge Function을 거친다.

## 9. 구현 단계 경계

현재 단계는 한국·미국 시가총액 유니버스, OpenDART·SEC 기업 식별자와 공시 탐색,
양국 재무 수집과 공시 식별값·표준 분기값 저장까지 담당한다.
불완전한 분기는 `review_required`로 남기며 표준 분기값을 교체하지 않는다.

다음 단계에서 YoY·QoQ·계절조정·Delta·마진 파생계층과 분기 가격,
Top10·Leader Score 및 프론트엔드 표시를 구현한다.

## 10. 백필 및 운영 일정

최초 유니버스 등록 시 각 기업의 최근 10년 분기재무를 백필한다. MacroWatch에 과거 추적 이력이 없는 완전 신규 기업도 기업 마스터와 소속 이력에 추가한 뒤 진입 시점 기준 최근 10년을 백필한다.

기업이 한 지수에서 이탈하더라도 다른 추적 지수에 유효한 소속이 남아 있으면 정기 수집을 계속한다. 모든 추적 지수에서 이탈하면 `earnings_index_memberships.effective_to`를 기록하고 정기 공시 수집 대상에서는 제외한다. 기업·식별자·기존 재무자료와 과거 순위는 삭제하지 않는다.

과거 추적 이력이 있는 기업이 모든 추적 지수에서 이탈했다가 다시 들어오면 재진입으로 판정한다. 재진입 시에는 새 기업을 만들지 않고 기존 기업에 새로운 소속 기간을 추가한다. 마지막으로 완성된 표준 분기의 다음 분기부터 재진입 시점의 최신 공시 분기까지 전체 예상 회계분기를 검사하고, 비어 있는 모든 분기를 기간 제한 없이 자동 백필한다. 따라서 7년 만의 재진입이면 최대 7년의 공백을 채운다.

재진입 백필은 최소 최근 10년만 조회하는 신규 진입 규칙을 적용하지 않는다. 다만 기존 저장 자료와 겹치는 분기는 재적재하지 않고, 정정공시는 기존 정정 규칙에 따라 반영한다. 누락 보완이 끝나면 해당 기업을 다시 정기 수집 대상에 포함한다.

기업이 다른 추적 지수에 계속 속해 있어 정기 수집이 중단되지 않은 상태에서 새로운 지수에 추가되는 경우에는 수집 관점의 재진입이 아니다. 기존 연속 재무자료를 그대로 사용하고 새 지수 소속 기간만 추가한다.

10년 원자료는 장기 분기 그래프와 YoY·QoQ 계산의 공통 입력이다. QoQ 계절 기준은 위에서 정의한 최근 5년 표본만 사용한다. 화면 표시 범위와 원자료 보존 범위는 분리하며, 지수 이탈 기업의 과거 재무와 순위도 삭제하지 않는다. 과거 지수 집계와 순위는 각 분기의 `effective_from`·`effective_to` 소속 기간을 기준으로 계산하므로, 재진입 백필로 확보한 이탈 기간 재무가 당시 지수 결과에 잘못 포함되지 않는다.

### 10.1 일일 증분 수집과 누락 복구

일일 증분 확인 시간은 다른 MacroWatch 자동작업과 겹치지 않도록 다음과 같이 고정한다.

- 미국 SEC: 한국시간 화~토요일 13:30
- 한국 OpenDART: 한국시간 월~금요일 19:30

고정된 최근 영업일을 휴일 달력으로 계산하지 않는다. 최초 실행은 최근 14일을 조회한다. 이후에는 소스별 마지막 성공 확인일보다 3일 앞에서 오늘까지 달력일 기준으로 겹쳐 조회한다. 수집이 오래 중단됐다면 체크포인트부터 오늘까지의 누락 구간 전체가 자동으로 포함된다. 공시 접수번호와 표준 분기의 고유키로 재조회된 자료를 제거한다.

이 방식은 설·추석 같은 장기 연휴, 미국과 한국의 서로 다른 휴장일, API 반영 지연, 자동작업 실패 후 재개를 별도 휴일 달력 없이 처리한다. DART의 18:00~19:00 익일 접수분은 다음 영업일 조회에서 반영한다.

### 10.2 집중 공시일과 호출 제한

공시 발견과 재무 수집을 분리한다. 날짜 범위의 공시목록을 먼저 한 번 조회하고, 추적 대상의 새 정기공시가 발견된 경우에만 기업·보고기간별 작업을 `earnings_ingestion_jobs`에 등록한다.

OpenDART 작업자는 같은 사업연도·보고서코드의 대기 작업을 최대 100개 회사씩 묶어 다중회사 주요계정 API로 처리한다. 최신 공시를 가장 높은 우선순위로 처리하고, 신규 기업의 10년 백필과 재진입 공백 백필은 그 뒤에 처리한다. 주요계정이 부족한 기업만 단일회사 전체 재무제표 보완 작업으로 넘긴다.

제공처마다 초당·일간·월간 제한을 독립 설정하고 공통 재시도 정책을 적용한다. 체크포인트와 작업 상태를 저장하므로 한 실행에서 모든 작업을 마치지 못해도 다음 실행이 미완료 작업부터 이어받는다. 완료된 작업의 재실행은 정정공시 또는 명시적인 복구 작업으로 한정한다.
